# Phase 4.1 social forecasting architecture

Branch `phase4-social-forecasting` starts at verified Phase 4 commit `447f164e808fee381fd3e9dbe8244583a0bed2f4`. The original single-agent modules, checkpoint format, data eligibility and historical results remain unchanged. This is offline research; it does not issue robot commands or train on Go2 tracks.

## Representation and leakage boundary

`forecasting.social_data.social_dataset(config, split)` first invokes the unchanged Phase 4 loader. It adds context to exactly those target windows; all recording checksums, split isolation, target keys, 8/12-step horizons and 0.4 s intervals stay intact. From the same recording at the target's last observed timestamp, select the nearest at most eight other identities within 3 m (distance then identity tie-break). A neighbor needs a current observation but not a complete past or any future annotation. Neighbors are not required to have eligible supervised target windows. Only exact matching observation timestamps populate history; missing entries remain masked. Future neighbor rows may exist in the loaded recording, but selection and model inputs never access them. Tests alter and remove them to enforce this property.

`SocialBatch` contains global metric XY target observations `[B,T,2]`, target validity `[B,T]`, neighbor observations `[B,K,T,2]`, neighbor validity `[B,K,T]`, shared times `[B,T]`, IDs `[B,K]` (`-1` padding), and target futures `[B,H,2]` for loss/evaluation only. `relative_positions` exposes valid neighbor XY minus the target's last observed XY. Invalid positions are zero-filled storage, not observed zero-valued locations. Dataset neighbors are selected before artificial robustness perturbations; selection is held fixed to isolate encoder sensitivity rather than detection/selection instability.

Source provenance and licensing caveats remain in [FORECASTING_DATASETS](FORECASTING_DATASETS.md). ZARA1/ZARA2 share a physical area. This is scene-identifier-held-out evaluation, not proof of unseen-location generalization. Training never opens test recordings. Context cannot cross a recording boundary even when timestamps or IDs coincide.

## Lightweight interaction model

`SocialTransformer` subclasses the original temporal implementation, reusing its two-layer Transformer encoder (width 64, four heads, feedforward 128, GELU, dropout 0.1), shared between target and neighbor histories. Default inputs remain consecutive displacements; a displacement touching an invalid observation is zeroed and missing timestamps are masked as attention keys. Sinusoidal encoding describes time only, never neighbor ordering. Each active neighbor must end at a valid current observation, so the last token summarizes its past. All-padding neighbors are excluded before attention to avoid undefined attention over an empty key set.

Add a bias-free projection of each neighbor's current position relative to the target origin to its temporal token. Take a masked mean across active neighbors, concatenate it with the target temporal token, then use LayerNorm, a width-128 GELU head and direct 12-step offsets. Reconstruction uses the target's last position (optional observed-heading rotation remains supported for complete targets). There are **87,128 parameters**, versus 78,680 for the original model. Zero-neighbor context is exactly a zero vector. This is not a CV fallback: the learned target-conditioned head still predicts. Social-disabled evaluation sets every neighbor mask false with identical trained weights.

Predictions are invariant to neighbor ordering up to floating-point summation tolerance in evaluation mode. Dropout makes individual training forwards stochastic; it is disabled at inference. Translating all valid target/neighbor coordinates translates predictions by the same amount. Tests check masked padding values (including NaNs), partial histories, zero neighbors, tensor shapes, gradients and these invariances.

Mean pooling is deliberately limited: it can discard count and cancel relative positions of symmetrically placed neighbors; it has no explicit neighbor-neighbor attention, map, intent, calibrated uncertainty or multimodal future. The wider output head and shared-encoder training also change the model even with social input disabled. Therefore, enabled-versus-disabled inference is the direct context-use diagnostic; social-versus-original improvements cannot automatically be attributed solely to interaction reasoning.

## Training, checkpoints and evaluation

`social_training.train_social` mirrors Phase 4's fixed seed/AdamW/SmoothL1/gradient accumulation/clipping/early-stopping protocol and selects only by clean validation ADE. It records both training and validation SmoothL1, validation ADE/FDE, source hashes, config, runtime and CPU-portable `social-temporal-transformer-v1` checkpoints. `load_social_checkpoint` checks version and loads with `weights_only=True`. The Phase 4 loader deliberately continues rejecting other model versions. The social model needs its dedicated loader; TrackOutput/ForecastOutput remain unchanged.

Optional training augmentation adds independent Gaussian XY noise to observed valid positions and masks interior target/neighbor observations, retaining endpoints. No supervision is perturbed. Masked observations never become features or keys. Heading alignment with missing target inputs is explicitly rejected rather than estimated from invalid samples.

`social_evaluation.evaluate_social` compares social, social-disabled, original single-agent and CV on paired target windows. Perturbation studies are rejected on the test split. Reports retain paired errors, the original GT-only motion categories, horizon prefixes and observed crowding groups: zero, one or two-plus selected neighbors. The internal `transformer` key inside each model's paired report denotes the model named by the enclosing key; it reuses Phase 4's metric schema. Crowding refers to target-window context under the declared radius/cap, not an inherent label for a whole scene. Empty strata have zero count and no fabricated metrics.

`run_social_forecasting.py` runs the predeclared three-seed/five-scene plan; `summarize_social_forecasting.py` verifies target-key hashes and independently reproduced original-model scores before aggregating. Standard deviations are across three seed runs (sample SD, ddof=1), not across correlated trajectory windows. No seed is chosen by test score. `social_visualization` plots observed neighbors only, GT target, CV and all neural variants; median-category examples and explicitly labeled extreme wins/failures prevent a successes-only presentation.

## Optional offline multi-track API

`social_adapter.multi_track_input` and `forecast_multitrack` consume existing TrackOutput objects in the same current odometry frame and clock. They require a caller-supplied `validated_ids` set representing external identity-quality review, a person label, currently observed Confirmed status, consistent history ID/frame/clock metadata, metric units and no future history. Duplicate IDs and unvalidated targets are fatal; rejected neighbors are recorded with reasons. The adapter cannot discover an ID switch concealed inside an otherwise plausible track: the attestation is a precondition, not an automated quality score.

Target history uses Phase 4's strict sampling/optional bounded interpolation. Partial neighbor histories are sampled onto those same times; unavailable samples stay invalid, optional interpolated samples are separately flagged. Selection uses current metric distance and the configured radius/count. `forecast_multitrack` returns the unchanged ForecastOutput plus a MultiTrackInput context object with IDs, validity/interpolation masks and rejections. Use the checkpoint's social configuration explicitly when calling the adapter. There is no assumption that anonymous LiDAR clusters are pedestrians and no invented calibration, confidence or covariance.

Source modules: `src/go2_perception/forecasting/social_{data,model,training,evaluation,adapter,visualization}.py`. No tracking internals or hardware adapters are modified. Real multi-person Go2 validation remains separate from the synthetic adapter tests.

A further limitation of this first pooling design is that relative-position projections are added linearly before averaging. It retains a context centroid and averaged temporal features, but can lose which motion belongs to which relative position. It should not be interpreted as explicit collision reasoning. The offline adapter also requires at least two actual neighbor observations for its history-integrity checks; the public dataset can represent a neighbor observed only at the cutoff. These conservative adapter restrictions intentionally narrow eligibility until real identity quality is established.
